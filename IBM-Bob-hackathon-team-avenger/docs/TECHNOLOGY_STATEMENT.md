## IBM Bob — five-layer integration

Cortex uses every extension surface IBM Bob exposes. This is not incidental — the depth of Bob integration is the core architectural decision.

### 1. MCP Server (`src/cortex-api/`)

The `cortex-api` service exposes five MCP tools over stdio transport, consumed by Bob at runtime:

| Tool | Description |
|---|---|
| `diary_save` | Persist a new memory entry with optional `file`, `line_start`, `line_end`, `tags` |
| `diary_recall` | Semantic search over all entries; returns top-k with `file:line` citations |
| `diary_link_code` | Attach a code location to an existing entry |
| `diary_feedback` | Boost or flag an entry (adjusts re-ranking score) |
| `diary_timeline` | Reverse-chronological listing with optional tag filter |

Bob connects via `~/.bob/settings/mcp_settings.json` (see `bob/MCP_CONFIG.md` for the exact JSON shape).

### 2. Custom Mode (`bob/custom_modes.yaml.example`)

The `📓 Cortex` mode sets Bob's system prompt to orient it toward capture and recall. It activates the skill, loads the rules, and registers the slash commands. Judges install it by copying `custom_modes.yaml.example` to `~/.bob/custom_modes.yaml`.

### 3. Skill (`bob/skills/cortex/`)

`SKILL.md` is a playbook Bob reads before every session in Cortex mode. It describes when to call each MCP tool, how to format entries, and how to handle the feedback loop. `examples.md` provides four annotated transcripts showing ideal Bob behaviour.

### 4. Slash Commands (`bob/commands/`)

Three slash commands are registered in the Cortex mode:

- `/diary-save <text>` — captures the current thought with secret detection
- `/diary-recall <query>` — semantic search, returns top 5 with citations
- `/diary-timeline [tag]` — reverse-chron listing, optional tag filter

### 5. Mode Rules (`bob/rules-cortex/`)

Five rules shape Bob's behaviour in Cortex mode:

| Rule | Innovation |
|---|---|
| `01-capture-style.md` | Formatting standards for entries |
| `02-no-secrets.md` | Refuse to save AWS keys, GitHub tokens, JWTs, private keys |
| `03-proactive-recall.md` | **Key innovation**: auto-surface entries when a file is opened |
| `04-agentic-auto-capture.md` | **Key innovation**: propose draft entry on task completion |
| `05-pending-actions.md` | Escalation queue for deferred Bob actions |

## watsonx.ai — embeddings and speech-to-text

### Embeddings (Granite Slate-30m)

`src/cortex-api/cortex_api/embeddings.py` calls the watsonx.ai embedding endpoint to convert entry text and search queries into 384-dimensional vectors. These are stored in a `sqlite-vec` virtual table and searched via approximate nearest-neighbour (L2 distance, converted to cosine similarity).

Fallback: if `EMBEDDINGS_PROVIDER=local`, the service uses `sentence-transformers/all-MiniLM-L6-v2` locally — same 384-dim space, no network required.

### IBM Speech to Text (Telegram voice)

`src/cortex-bot/cortex_bot/transcription.py` downloads Opus voice memos from Telegram, sends them to the IBM STT endpoint, and returns the transcript. The transcript is then passed through secret detection before being saved as a `telegram-voice` entry.

Fallback: if `STT_PROVIDER=local`, the service uses `faster-whisper` (MIT licence) locally.

## Architecture summary

```
IBM Bob (📓 Cortex mode)
    │  MCP stdio
    ▼
cortex-api (FastAPI + MCP SDK, port 8080)
    │  SQLite + sqlite-vec
    │  watsonx.ai embeddings
    │  IBM STT (via cortex-bot)
    ├──► cortex-bot (Telegram, voice capture)
    └──► cortex-web (React + Carbon, port 8081)
         cortex-mobile (Expo React Native)
```
